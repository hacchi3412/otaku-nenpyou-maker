# 公開前チェックリスト

オタク年表メーカーを公開するにあたって確認しておきたい項目をまとめたもの。
大きく分けて「1. 自分で事前に確認する項目」と「2. ユーザーテストで確認する項目」の2部構成。

---

## 1. 事前確認（自分でチェックする項目）

### 1.1 実機でのシェア機能確認（最優先）

開発はサンドボックス環境で行っており、実際のスマホ・実際のネット回線・実際のXへの投稿は未確認。
このアプリの核となる機能であり、かつ環境によって挙動が変わることが開発中に何度も判明した箇所なので、最優先で確認する。

- [ ] iOS Safari：「シェア」を押すと共有シートが開き、画像・キャプション・URLが正しく渡る
- [ ] iOS Chrome：同上（内部エンジンはSafariと同じWebKitだが、念のため個別に確認）
- [ ] Android Chrome：共有シートに出てくるアプリ（X、LINEなど）で実際に開いて内容が正しい
- [ ] PC（Chrome/Edge/Safari/Firefoxのいずれか）：ボタン表示が「Xでシェア」になり、画像ダウンロード→X投稿画面が開く一連の流れが動く
- [ ] iOSで「画像として保存」を押すと、共有シート経由で実際に写真アプリに保存される

### 1.2 リンク・OGP確認

- [ ] Xに公開URLだけを貼った場合、リンクカードが表示される（画像添付なしのケースは未検証）
- [ ] LINEやSlackなど他サービスに公開URLを貼った場合のプレビュー表示を確認
- [ ] `https://hacchi3412.github.io/otaku-nenpyou-maker/privacy.html` に実際にアクセスできる（ビルド成果物には含まれることは確認済みだが、公開URLでは未確認）
- [ ] お問い合わせフォームを実際に1件送信し、Googleフォーム側に通知が来ることを確認

### 1.3 境界値・入力データチェック

| 項目                           | 確認する境界値                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------------ |
| ジャンル名                     | 空、1文字、15文字ちょうど、絵文字・サロゲートペア文字（文字数カウントがズレないか）  |
| 一言コメント                   | 空、30文字ちょうど                                                                   |
| 見出しの名前                   | 空、10文字ちょうど、絵文字（フォント非対応文字は豆腐表示になる想定・仕様として許容） |
| 年ごとの項目数                 | 3個ちょうど（上限）、上限到達時にドラフト欄が消える                                  |
| 継続項目                       | 同じジャンル名で5年以上連続、3レーン全部埋まった状態の見た目崩れ                     |
| 「＋もっと過去の年を追加する」 | 何度も押して年数がかなり増えた状態でのパフォーマンス・書き出し画像の高さ             |
| 空の年表                       | 何も入力せず「画像として保存」「シェア」を押した場合の挙動が想定通りか               |

- [ ] 上記の境界値を一通り試す

### 1.4 環境横断チェック

- [ ] PC・iPhone・Android × Chrome・Safari・Edge等、一通りの組み合わせで基本操作（入力→プレビュー反映→保存）を確認
- [ ] プライベートブラウジング：localStorageが制限される環境での挙動（既知の問題として対処済みだが実機で再確認）
- [ ] 複数タブで同時に開いた場合：片方の編集がもう片方に反映されない・上書きされる可能性がある点は許容範囲か
- [ ] ダークモード端末：システムがダークモードでもアプリはライト固定デザインで違和感がないか

### 1.5 運用・法務面の最終確認

- [ ] GA4管理画面で実際にデータが入り始めていることを確認（測定ID: `G-RY0263PVXG`）
- [ ] プライバシーポリシーの記載内容が実態と合っているか最終読み合わせ

## 2. ユーザーテスト（2名想定）

隣で実際に使ってもらい、思考発話法（操作しながら思ったことを声に出してもらう）で観察する。

### 2.1 事前準備

- [ ] アプリの使い方は事前に説明せず、URLだけ渡して「好きに触ってみてください」で始める
- [ ] テスト前にブラウザのlocalStorageをクリアしておく（シークレットウィンドウで開くと簡単）。初見の反応を見るため
- [ ] 最初に「操作しながら、思ったこと・迷ったことをそのまま声に出してください」と伝える
- [ ] 可能なら1人はスマホメイン・1人はPCメインなど環境を分ける。オタク文化に明るくない人も混ぜられるとタイトルの伝わり方まで見られる
- [ ] 観察側の心構え：詰まっていてもすぐに答えを教えない。10〜20秒待ってから「今何をしようとしてますか？」と聞く（誘導しない）

### 2.2 お願いするタスク（手順ではなくゴールで伝える）

1. 「最近ハマっているものを、思いつくままに何年か分入力してみてください」
2. 「作った年表を画像として保存してみてください」
3. 「その年表をXでシェアしてみてください」（実際の投稿は不要、共有画面が開くところまででOK）
4. （余裕があれば）「見出しの部分を、自分らしい呼び方に変えてみてください」
5. （余裕があれば）「入力した内容を全部消してみてください」

### 2.3 観察ポイント

| 場面                           | 見るべきこと                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| 開いた直後                     | 説明なしで「何のアプリか」理解できているか（迷う素振り・沈黙が長くないか）                 |
| ジャンル名入力                 | プレースホルダーだけで迷わず打ち始められるか                                               |
| コメント・カラー選択           | 項目入力後に現れる欄に自然に気づくか、見落とさないか                                       |
| 継続チップ（前年/翌年から）    | 存在に気づくか、意味が伝わるか（気づかなくても致命的ではないが観察価値あり）               |
| 「画像として保存」             | 押した後、保存されたことに気づけているか（特にスマホで迷う様子がないか）                   |
| 「シェア」                     | 共有シートが開いた時に戸惑わず選べるか、ヒント文言を読んでいるか無視しているか             |
| 「全部消す」                   | 確認ダイアログの文言で「本当に消していいか」判断できているか、誤操作を後悔する反応がないか |
| 「＋もっと過去の年を追加する」 | 存在に気づくか（画面下部にあるので、必要になるまで見えないのは想定通り）                   |

### 2.4 終了後に聞く質問

- [ ] 「このアプリ、一言で言うとどんなアプリでしたか？」（理解度の確認）
- [ ] 「操作中、迷った・戸惑った瞬間はありましたか？」
- [ ] 「シェアボタンを押したとき、何が起きると思っていましたか？」（期待と実際のズレの確認）
- [ ] 「もう一度使うとしたら、何を変えてほしいですか？」
- [ ] （継続チップに気づかなかった場合）「実はこういう機能があるんですが、知っていたら使いたいと思いますか？」

### 2.5 進行のコツ

- 1人あたり10〜15分あれば十分（このアプリの規模なら長時間は不要）
- メモは「どこで詰まったか」「かかった体感時間」「表情・反応」を中心に。改善案はその場で考えず、後でまとめて検討する方が客観的
- 2人という少人数でも「同じ場所で2人とも詰まった」となれば、それは高確率で直すべき箇所。逆に1人だけの反応は参考程度に留める
